# Орбита — цифровой деканат будущего

Рабочий прототип личного кабинета студента для конкурса «Цифровой деканат будущего».
**Это концепт, а не официальный сервис вуза.** Университет «Горизонт» вымышлен. Все персональные данные, учетные записи, оценки и документы являются вымышленными. Расписание и академические правила смоделированы на основе открытых данных и образовательных практик вуза.

Расписание, баллы, справки, заявления, связь с деканатом и объявления собраны в одном кабинете. Он работает на телефоне от 360 px и на компьютере.

## Что умеет кабинет

**Обязательное ядро**
1. **Вход и профиль.** Вход по логину и паролю. Профиль: ФИО, факультет, направление, курс, группа. Личные данные по умолчанию скрыты.
2. **Расписание.** Пары на сегодня и на неделю, аудитория и преподаватель, четность недели. Отмены, переносы, замены и смены аудитории подсвечены. Расписание выгружается в календарь телефона (.ics).
3. **Успеваемость.** Рейтинг по дисциплине (0–100) складывается из трех срезов (вес 1), посещаемости в процентах от посещенных пар (вес 0,5) и работы на парах (вес 0,3). Зачет: от 70 — автомат, ниже — выход на зачет. Экзамен: допуск от 50, итог — 60% рейтинга и 40% ответа на экзамене. Перевод в пятибалльную оценку и ECTS: 90–100 A, 82–89 B, 75–81 C, 67–74 D, 60–66 E, ниже 60 F. Есть шкала оценивания, пороги «автомат от 70» и «допуск от 50», расписание сессии и зачетка.
4. **Заявки и справки.** 7 услуг: справка об обучении, выписка из зачетки, справка о стипендии, ректорская пересдача, материальная помощь, академический отпуск, вопрос в деканат. Для заявлений формируется типовое заявление в PDF (шапка «Декану … от студента/студентки …» с ФИО в нужном падеже, текст, дата и подпись) — его можно скачать, распечатать и подписать. Справка об обучении — PDF в том же оформлении, с QR-кодом и подписью сотрудника; род («является студентом/студенткой») и падежи ФИО учитываются по полу. Форма строится по схеме с сервера. Статус показан шкалой «Принята → В работе → Готово», к каждой заявке есть переписка с деканатом и оценка качества.
5. **Уведомления.** Объявления деканата (для всех, факультета или группы), изменения расписания, смены статуса заявок, автоматические напоминания о дедлайнах за 48 часов.

**Свои идеи**
- **Мероприятия.** В ленте — события (конференции, открытые лекции, мастер-классы) с кнопкой «Добавить в календарь» и отдельной страницей с описанием. Если мероприятие пересекается с парами, студент видит предупреждение и может добавить его все равно; в расписании пересекающиеся события стоят стопкой со сдвигом, как в календаре. Создают мероприятия деканат и преподаватели.
- **Задания к парам.** Пары в расписании кликабельны: в карточке пары видны задания с дедлайнами, которые прикрепил преподаватель. Те же дедлайны — на главной, со ссылкой «к паре …». Есть и дедлайны без пары.
- **Кабинет преподавателя.** Расписание по своим группам, отметка посещаемости (сразу влияет на пропуски и рейтинг студента), задания с дедлайнами, сводка посещаемости, публикация мероприятий и заявки на перенос пары, которые согласует деканат; после одобрения студенты видят перенос в расписании, преподаватель — уведомление.
- **Облегченная версия `/lite`.** Страницы собираются на сервере: без JavaScript, анимаций и шрифтов. В ней можно работать с заявками: студент подает и уточняет, деканат меняет статусы и согласует переносы, преподаватель отмечает посещаемость и просит перенос. Если основной кабинет не открылся за 4 секунды, сервер отвечает дольше 5 секунд или браузер сообщает о медленной сети, внизу появляется предложение перейти в облегченную версию. Кнопка с пером в шапке (рядом со сменой темы), ссылка на странице входа и в профиле.
- **Расписание по открытым данным вуза.** Пары трех групп (ФУП, МО, МЖ) взяты из опубликованного расписания, ФИО преподавателей исключены. Время пар: для МО, ФУП и МЖ обед после 3-й пары, для МЭО, МП, МБ и ИМТУР — после 2-й (`server/academic.js`).
- **Посещаемость: пропуски и проходы.** Пара — 2 академических часа. Показываем «N ак. ч. из 30 ак. ч.»; после 30 ак. ч. — выговор, и шкала переходит на «из 60 ак. ч.» с пометкой «риск отчисления». Пропуски по справке не учитываются. Входы и выходы через турникеты (СКУД): когда пришел, когда ушел, сколько часов провел в университете за день и за неделю. Сотрудник деканата видит то же по каждому студенту.
- **Пересдачи назначают деканат и кафедра.** Студенту не нужно подавать заявление: пересдача появляется в расписании, баннером на главной и в ленте. Заявление остается только на **ректорскую пересдачу**.
- **Оформление «жидкое стекло».** Полупрозрачные панели с размытием, без градиентов. Акцент по умолчанию — navy blue; в профиле можно выбрать акцентный цвет и световую схему (светлая, темная, как в системе).
- **«Сейчас / Далее».** Главный экран показывает, какая пара идет и куда идти дальше.
- **Электронная справка с QR-кодом за секунды.** Ее подлинность проверяется на публичной странице `/verify/…`, где ФИО частично скрыто.
- **Помощник «Спроси Орбиту».** Отвечает по данным студента («что у меня завтра?», «сохраню ли стипендию?») и предлагает действие. С ключом Claude API работает через ИИ, без ключа — по встроенным правилам. ФИО и контакты в ИИ не передаются.
- **Быстрый поиск по Ctrl+K.** Ищет по разделам и услугам.
- **Дедлайны-чеклист**. Кабинет устанавливается на телефон как приложение (PWA).
- **Кабинет сотрудника.** Очередь заявок с просрочками, смена статуса (при отказе причина обязательна), ответы студенту, объявления, изменения расписания с мгновенным уведомлением группы, посещаемость и СКУД по студентам, назначение пересдач.
- **Безопасность для студента.** Видны активные сеансы и последние входы. Можно выйти на других устройствах или из всех сеансов сразу и сменить пароль.

## Безопасность

| Требование | Как сделано |
| --- | --- |
| Студент видит только свои данные | Личность берется только из сессии. Каждый объект ищется с условием «принадлежит текущему студенту», иначе ответ 404. Идентификаторы заявок случайные (`Z-7K3Q-9ABX`), их нельзя перебрать. Проверено тестами. |
| Пароли не хранятся в открытом виде | scrypt (N=16384) с уникальной солью, сравнение за постоянное время. Для несуществующего логина тоже считается хеш, чтобы по времени ответа нельзя было определить, есть ли такой пользователь. |
| Сессии | 256-битный случайный токен в cookie `HttpOnly; SameSite=Lax; Secure` (в продакшене `__Host-`). В базе лежит только SHA-256 токена. Сессия истекает после 12 часов бездействия. |
| Перебор паролей | После 5 ошибок вход блокируется на 10 минут. |
| CSRF / XSS / встраивание | Изменяющие запросы требуют заголовок `X-Orbita`. Строгий CSP без inline-скриптов, весь текст экранируется. Заданы `X-Frame-Options: DENY`, `nosniff`, HSTS. |
| Персональные данные | Номер зачетки, e-mail, телефон и дата рождения хранятся зашифрованными (AES-256-GCM). Ключ лежит в `DATA_KEY`, не в коде. |
| Ключи сервисов | `ANTHROPIC_API_KEY` есть только в окружении сервера. Браузер обращается к нашему API, ключ ему не виден. |
| Журнал | Входы, неудачные попытки и действия сотрудников пишутся в `audit_log`. IP хранится только в виде хеша. |

## Запуск

```bash
npm install
npm start          # http://localhost:3000, база с демо-данными создается сама
npm test           # 21 автотест безопасности и сценариев
```

Нужен Node.js 22.13 или новее (встроенный SQLite). Сборка фронтенда не нужна.

### Развертывание по ссылке
- **Render.com:** в репозитории лежит `render.yaml` (New → Blueprint), `DATA_KEY` генерируется автоматически.
- **Свой сервер (VPS):** пошаговая инструкция в [docs/DEPLOY.md](docs/DEPLOY.md) — Node.js 22, systemd, Caddy с HTTPS, ночной сброс демо-базы. Готовые конфиги в `deploy/`.
- **Docker:** `docker build -t orbita . && docker run -p 3000:3000 -e DATA_KEY=... orbita`.
- Подойдет любой хостинг с Node 22: Railway, Timeweb Cloud, Yandex Cloud Serverless Containers. Если задать `ANTHROPIC_API_KEY`, помощник начнет отвечать через Claude.

На бесплатных тарифах диск может очищаться при перезапуске. Тогда демо-база создается заново, и это удобно для показа жюри.

## Масштабирование
- Сервер не хранит состояние: сессии лежат в базе, поэтому можно запустить несколько экземпляров за балансировщиком.
- SQLite выбран для прототипа. SQL в схеме переносимый, и для тысяч студентов база меняется на PostgreSQL без изменения логики.
- Счетчик попыток входа и лимит запросов к помощнику сейчас хранятся в памяти процесса. При нескольких экземплярах их нужно перенести в Redis.
- Статика кэшируется (шрифты — на год). Сервис-воркер держит оболочку приложения, персональные данные не кэширует.
- Расписание можно наполнять парсером открытых данных вуза: таблицы `lessons` и `schedule_changes` для этого и сделаны.

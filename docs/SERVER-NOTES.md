# Развертывание «Орбиты» на личном VPS: что сделано и что осталось

Файл для Claude Code и других ИИ-агентов. Составлен 22 ноября 2026 года по итогам сессии, в которой пользователь шаг за шагом разворачивал проект `jeenien/e-dekanat` на своем сервере, чтобы показать его жюри конкурса.

Все правила проекта остаются в силе: см. `CLAUDE.md` в корне репозитория (данные вымышлены, пометка о демо-прототипе не удаляется, секреты только в окружении).

В файле нет секретов. `DATA_KEY`, пароли и закрытые ключи сюда не записаны и записывать их не нужно.

## 5. Отличия от `docs/DEPLOY.md` и найденные проблемы

Это самое ценное для следующих правок в репозитории.

### 5.1. Ubuntu 26.04: Node.js нужно закреплять за NodeSource

В репозитории Ubuntu 26.04 есть собственный пакет `nodejs` версии `22.22.1+dfsg...`. По номеру версии он выше, чем пакет NodeSource (`22.22.1-1nodesource1`), поэтому после `setup_22.x` apt без закрепления может поставить пакет Ubuntu. На сервере создан файл `/etc/apt/preferences.d/99-nodesource-nodejs`:

```
Package: nodejs
Pin: origin deb.nodesource.com
Pin-Priority: 1001
```

Шаг 6 в `docs/DEPLOY.md` про это не говорит. Стоит добавить примечание для Ubuntu 26.04 и проверку `node --no-warnings -e "require('node:sqlite')"`.

### 5.2. Ошибка в `deploy/orbita-reset.service` (исправлена в репозитории)

Служба вызывает `/usr/bin/runuser`, а на этом сервере такого пути нет (команда `runuser` из оболочки работает, потому что лежит в другом каталоге из `PATH`). Что произошло при первом запуске: первая команда службы остановила приложение, вторая упала с `status=203/EXEC`, третья (запуск приложения обратно) не выполнилась, и сайт остался выключенным. Приложение было возвращено вручную: `systemctl start orbita`.

Опасность: если бы так осталось, ночной таймер в 04:30 каждый раз выключал бы сайт и не включал обратно.

Исправленная служба, которая сейчас стоит на сервере (без `runuser`, приложение запускается обратно при любом исходе благодаря `ExecStopPost`):

```ini
[Unit]
Description=Orbita - пересоздание демо-базы

[Service]
Type=oneshot
User=orbita
Group=orbita
WorkingDirectory=/opt/orbita
EnvironmentFile=/etc/orbita.env
# остановить приложение (с правами root, несмотря на User=orbita)
ExecStartPre=+/bin/systemctl stop orbita
ExecStart=/usr/bin/node --no-warnings scripts/reset-db.js
# запустить приложение обратно в любом случае, даже если сброс упал
ExecStopPost=+/bin/systemctl start orbita
```

Проверено на сервере: запуск `systemctl start orbita-reset.service` пересоздает базу (`Демо-база пересоздана: /var/lib/orbita/orbita.db`), затем `orbita` в состоянии `active` и `/healthz` отвечает. Скрипт `scripts/reset-db.js` проверен и в песочнице: завершается с кодом 0 и не занимает порт.

Исправленный вариант перенесен в `deploy/orbita-reset.service` в репозитории.

`deploy/update.sh` запускается под `root` и вызывает `runuser` через `PATH`, поэтому он этой проблемы не имеет.

### 5.3. Вход по IP-адресу через сертификат Let's Encrypt для IP

`docs/DEPLOY.md` говорит, что без домена войти нельзя, потому что cookie защищены флагом `Secure` и префиксом `__Host-`. Это верно для http, но Let's Encrypt с января 2026 года выдает сертификаты на IP-адреса (только короткоживущие, около шести суток), и Caddy умеет их запрашивать и продлевать. Блок в `/etc/caddy/Caddyfile`:

```
109.120.152.121 {
	tls {
		issuer acme {
			profile shortlived
		}
	}
	encode zstd gzip
	reverse_proxy 127.0.0.1:3000
}
```

Рядом остался блок для DuckDNS:

```
orbita-gorizont.duckdns.org {
	encode zstd gzip
	reverse_proxy 127.0.0.1:3000
}
```

Нужен Caddy достаточно новой версии (поддержка профилей сертификатов и IP-идентификаторов, актуальные 2.11.x). Если `caddy validate` ругается на `profile`, обновите пакет: `apt -y install --only-upgrade caddy`. Сертификат продлевается автоматически, пока сервер включен и порты 80/443 открыты.

Справки с QR-кодом строят ссылку по адресу, с которого открыт сайт, поэтому при входе по IP QR ведет на `https://109.120.152.121/verify/...`.

| Что | Команда |
| --- | --- |
| Состояние приложения и Caddy | `systemctl is-active orbita caddy orbita-reset.timer` |
| Проверка приложения изнутри | `curl -s http://127.0.0.1:3000/healthz` |
| Проверка снаружи | `curl -sI https://109.120.152.121 \| head -1` (ожидается `HTTP/2 200`) |
| Логи приложения | `journalctl -u orbita -n 100 --no-pager` |
| Логи Caddy и сертификатов | `journalctl -u caddy -n 100 --no-pager` |
| Обновить код из `main` | `sh /opt/orbita/deploy/update.sh` |
| Сбросить демо-данные вручную | `systemctl start orbita-reset.service` |
| Ближайший ночной сброс | `systemctl list-timers orbita-reset.timer --no-pager` |
| Проверить конфиг Caddy | `caddy validate --config /etc/caddy/Caddyfile` |
| Применить конфиг Caddy | `systemctl reload caddy` |

Ночной сброс в 04:30 удаляет все, что делали пользователи (заявки, отметки, смену паролей), и возвращает демо-аккаунты к исходному состоянию. Перед показом жюри стоит выполнить сброс вручную.

Демо-аккаунты (из `README.md`): `anna` / `Orbita-Anna-2026`, `timur` / `Orbita-Timur-2026`, `nika` / `Orbita-Nika-2026`, `teacher` / `Orbita-Teacher-2026`, `dekanat` / `Orbita-Staff-2026`.

- На сервер у агента доступа нет. Все команды выполняет пользователь в своем терминале и присылает вывод. Команды лучше давать небольшими блоками с понятным ожидаемым результатом.
